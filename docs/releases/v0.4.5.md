# Claude Context Continuity v0.4.5

## 版本概述

让协作会话在换窗后仍能被正确识别：原生 Session ID 虽然变化，cclaude 可以通过已登记历史关联到当前在线会话。模型不必仅凭一个不同的 Session ID 判断任务已经换人。

相较 v0.4.2，本版还修复恢复会话时早期历史引用丢失，以及连续子代理历史分片无法接入原生恢复入口的问题。继续要求 **Python 3.10+、tmux 和 Claude Code >=2.1.304**。

## 主要更新

- **自动展示 peer 跨窗关联。** 原生 `ListAgents` 后附加只读关联信息；成功发往唯一具名 peer 的 `SendMessage` 也可获得同样的信息。保留原工具结果和消息投递机制。
- **按旧 Session ID 查询当前入口。** 新增 `claude-context peer-lineage --session-id UUID`，搜索全部已确认窗口，支持多次换窗前的 ID；省略参数可查看简要列表。
- **只报告可核实的关联。** 使用原生在线会话的 Session ID、进程 ID 和既有历史登记，不凭名字或工作目录猜测。待确认、冲突或不可用的绑定不选定接续会话；查询不会发送消息或增加任务授权。
- **恢复早期历史引用。** 恢复到含有新用户指令的会话时，仍保留已验证的历史来源，同时以该会话的真实用户指令决定授权。既有 `tui-recover` 可补回遗漏的历史登记。
- **接通连续的子代理历史分片。** 按原生 `uuid`／`parentUuid` 祖先关系识别连续分片，保留原输入，再为原生 loader 提供完整历史。竞争分支、缺失前驱和身份冲突仍会阻止恢复，不以不同文件本身判定分叉。

本次定向回归 **211 项测试、126 个 subtest 通过**。隔离安装的 wheel 已通过真实本地历史查询，安装后的原生 `ListAgents` 与具名 `SendMessage` 已实际返回新增关联信息。既有历史恢复修复沿用有效的原生 consumer 验收，本次未重复完整测试套件。

## 升级说明

```sh
python3 -m pip install --upgrade "git+https://github.com/macchen123/claude-context-continuity.git@v0.4.5"
```

也可以安装本 Release 附带的 wheel，并用 `SHA256SUMS` 校验。查询示例：

```sh
claude-context peer-lineage --session-id "<旧-session-UUID>"
```

新增关联功能由每次 hook 调用和 CLI 读取新版代码。安装不会热替换已经运行的常驻控制器；从较早版本升级、需要让全部历史恢复修复生效时，请在当前工作到达安全边界后正常退出目标原生进程，再用 `cclaude` 启动或恢复。仅 `/clear` 或重新 attach 不等同于重新加载控制器。

已有历史和笔记无需删除。原生权限、子代理身份检查、队列及消息投递规则保持不变。
